Agent frameworks — reading room

Three Ways to Build the Same Loop

Three guides to agentic development, built from the same source corpus and meant to be read in order. Each one answers the same question at a different level of abstraction: what is actually sent to the model, and who decides what happens next.

How to read these

Same machine, different amounts of clothing

Every agent framework abstracts the same three things — orchestration, tool calling, and structured outputs. The guides are ordered by how much of that a library does for you, so the sequence below is a ladder, not a menu. Start at the bottom rung and each abstraction above it stops being magic.

What CrewAI Actually Sends

An opinionated framework, read through its traces.

You write role, goal, and backstory; CrewAI composes the system prompt. That single decision explains everything downstream — YAML separated from code, tasks as first-class objects, one-line switching between code-driven and LLM-driven orchestration, and an implicit context default that quietly grows your prompt on every task.

Side by side

One question, three answers

The rows are the decisions every agent has to make. The columns are where each guide puts them.

Decision Plain Python Agents SDK CrewAI
Who writes the system prompt you, literally you, via instructions the framework, from role / goal / backstory
Who owns the loop your while Runner.run() Crew.kickoff()
How tools are declared a dict allow-list you maintain @function_tool @tool + a built-in library
Context between steps whatever you append whatever you pass all prior outputs, unless narrowed
Memory across runs a list you write Session, opt-in memory=True, opt-in
Delegation you call the next function handoffs or agents-as-tools manager agent + delegation
Bounding a runaway loop yours to build guardrails + tripwires not covered in the sources
A caveat that applies to all three

No source in the corpus benchmarks these against each other, and none measures framework overhead against a hand-written loop. The guides reason from documented behaviour and traces, not from measurement — and each one says so where it matters.
